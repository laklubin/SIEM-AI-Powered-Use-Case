A companion library to the ATLAS/OWASP set, pointed the other way. Those use cases cover attacks against AI systems; these cover attacks carried out with AI — generated phishing and deepfakes, autonomous agent intrusion, adversarial evasion of security ML, shadow-AI data loss, and abuse of the LLM and model-supply-chain estate. Each entry is written to be actionable from telemetry you already collect.

Every use case carries three fields: use case name · log source · sample log — plus a detection note and an indicative ATT&CK/ATLAS mapping.

Sample logs are synthetic. Every log line on this page was written by hand to illustrate the field names, shape and discriminating values an analyst should look for in that source. They are not captured telemetry, they are not vendor-published samples, and field names vary by product version and configuration — validate against your own schema before building content from them. Hostnames, accounts and domains are fictional; IP addresses use the RFC 5737 documentation ranges or RFC 1918 private space.

Framework mappings are indicative. ATT&CK and ATLAS technique IDs are analyst-assigned for orientation, not certified mappings — neither framework publishes a taxonomy for AI-as-the-weapon tradecraft, which is precisely the gap this library fills. Severity is a scoping judgement, not a risk rating for your environment.
